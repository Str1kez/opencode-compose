## [Unreleased]

### Добавлено

- README: как дать контейнеру прокси через `proxies` в `~/.docker/config.json` и почему сборка без питона может упасть на образе uv (обход через `UV_REGISTRY`).
- Визард определяет Docker-движок (colima, OrbStack, Docker Desktop) и работает поверх любого. Новая стадия «Репозиторий внутри движка» проверяет, что WORKSPACE виден в VM colima. Если не виден, визард печатает точную команду `colima start --mount $WORKSPACE:w --mount $HOME:w` и запускает её только после подтверждения. Перед перезапуском предупреждает, что `colima stop` остановит все контейнеры в VM. `$HOME` в команде остаётся потому, что `--mount` заменяет весь список, а конфиги для контейнера лежат в домашней папке.
- Git push из контейнера по SSH. Визард получил шаг «Git-доступ по SSH»: показывает приватные ключи из `~/.ssh`, останавливает на ключе с passphrase и советует deploy-ключ без неё, берёт хост из remote репозитория, собирает known_hosts через `ssh-keyscan` и просит сверить fingerprint. Ключ и known_hosts монтируются только на чтение, git ходит ими через `GIT_SSH_COMMAND`, так что `.gitconfig` хоста и его `include` не мешают. known_hosts лежит в `.git-ssh/`, она в `.gitignore`.
- Смоук `tests/smoke-git-push.sh`: поднимает харнесс в отдельном compose-проекте рядом с одноразовым sshd и проверяет push из контейнера.
- Питон-профиль в визарде: `build-essential` и uv (0.13.8, образ закреплён по digest) прямо в образ, плюс поле для dev-библиотек проекта. Системный питон не ставится, его приносит `uv sync`.
- У контейнера свой `.venv`: отдельный volume поверх `WORKSPACE/.venv`. Хостовый macOS-venv контейнер не видит и не перезаписывает (ADR 0003).
- README переписан под любой Docker-движок: colima как рекомендуемый дефолт с установкой, подвох colima mount для WORKSPACE вне `$HOME`, git-доступ через deploy-ключ без passphrase, питон-профиль и изоляция `.venv`.
- Смоук `tests/smoke-python-venv.sh` для питон-профиля и `.venv` в отдельном volume, плюс `tests/wizard-functions.sh`: гоняет функции визарда через stdin без docker.
- Визард запоминает движок (`DOCKER_ENGINE` в `.env`). Если docker смотрит не в тот движок, что в прошлый раз, или контекстов несколько, он спрашивает, какой взять, и предлагает прошлый по Enter. colima находится и по `DOCKER_HOST` или контексту `default`, если их endpoint лежит в `~/.colima` или `$COLIMA_HOME`.
- После запуска визард делает из контейнера `git push --dry-run` и показывает результат. Ошибка не фатальна.
- Remote через псевдоним из `~/.ssh/config` визард распознаёт по `ssh -G`, печатает готовый `git remote set-url` с настоящим хостом и пропускает стадию. Раньше он делал `ssh-keyscan` по псевдониму.
- Volume с `.venv` свой на каждый репозиторий (`VENV_VOLUME` в `.env`, визард выводит его из `WORKSPACE`). Смена `WORKSPACE` больше не подсовывает venv другого проекта. Визард сам создаёт `WORKSPACE/.venv` как точку монтирования, чтобы на Linux Docker не создал её от root.
- В репозитории `.shellcheckrc`: `shellcheck` на `scripts/setup.sh`, `docker/entrypoint.sh` и `tests/*.sh` чист.
- В корпоративной сети, где `deb.debian.org` закрыт, визард спрашивает папку с apt-настройками внутреннего зеркала и копирует их в `docker/apt/` (в `.gitignore`). Сборка применяет их до первого `apt-get`: `*.sources` и `*.list` заменяют стандартные источники Debian, `*.conf` ложатся в `apt.conf.d`, `*.crt` становятся доверенными сертификатами.
- `UV_REGISTRY` в `.env`: образ uv можно тянуть через зеркало, если ghcr.io закрыт. Digest по-прежнему закрепляет ровно тот же uv.
- Харнесс можно поднять в нескольких репозиториях одновременно. Визард выводит из `WORKSPACE` имя compose-проекта (`COMPOSE_PROJECT_NAME` в `.env`) и порт из диапазона 4097-4996, так что `up` во втором репозитории больше не пересоздаёт контейнер первого. Повторный запуск визарда для того же репозитория имя проекта и порт не меняет, уже настроенный репозиторий остаётся проектом `opencode`. Без визарда проект по-прежнему `opencode`.

### Изменено

- uv в питон-профиле ставится через pip из PyPI-индекса `UV_PIP_INDEX_URL` (по умолчанию `https://pypi.org/simple`), а не из образа `astral-sh/uv` на ghcr.io. В корпоративной сети, где нет ни ghcr.io, ни зеркала с этим образом, питон-профиль теперь собирается: визард спрашивает адрес внутреннего индекса. pip работает в одноразовой стадии сборки, в образ попадает только бинарь `uv`, системного питона и pip там по-прежнему нет. Версия та же (0.13.8), закрепление переехало с digest образа на хэши колёс для amd64 и arm64 в `docker/uv-requirements.txt`. Без питон-профиля стадия с pip не собирается вовсе, так что сборка не-питон проекта в закрытой сети больше не падает на uv. `UV_REGISTRY` убран, повторный запуск визарда удаляет его из `.env` и сохраняет питон-профиль.
- README описывает модель угроз: контейнер не защищает хостовый git от скомпрометированного агента, потому что агент пишет в `.git/` рабочей копии. Там же совет, что проверять после недоверенных сессий.
- Домашняя папка контейнера теперь своя у каждого репозитория: визард выводит `HOME_VOLUME` из `WORKSPACE`. Раньше она была общей, и агент из одного репозитория мог подложить код, который запускался в контейнере другого с его deploy-ключом (ADR 0004). При следующем запуске визарда уже настроенный репозиторий переезжает на новую домашку, логин в провайдерах и загрузка opencode повторятся; визард предупреждает об этом и советует удалить старую общую домашку, когда все репозитории перешли (в ней могла остаться закладка и токены провайдеров). Ручное значение `HOME_VOLUME`, не равное общему имени, визард тоже заменяет и называет прежнее значение в предупреждении. Оставить общую можно, прописав в `.env` `HOME_VOLUME=opencode_opencode-home`. `docker compose down -v` удаляет только домашку этого репозитория.
- Из списка пакетов убраны `bash`, `tar` и `tzdata`: они уже есть в debian slim. Списки apt чистятся через `rm -rf /var/lib/apt/lists/*`, cache mount не используется, причина записана в Dockerfile.
- У образа появились OCI-лейблы `title`, `description` и `source`.
- Занятый UID в базовом образе даёт понятную ошибку сборки с подсказкой про `OPENCODE_UID`, как уже было с GID.
- В контекст сборки попадает только `docker/`: `.dockerignore` отсекает `.env` с паролем сервера, `.git`, `.scratch` и `tests`.
- Корпоративные apt-настройки подключаются к сборке через bind mount, а не `COPY`, и `*.conf` удаляются в том же шаге, где идёт `apt-get`. Раньше `*.conf` с прокси и логином к зеркалу оставались в слоях образа навсегда. Источники и сертификаты в образе остаются, поэтому `apt-get install` руками в запущенном контейнере до зеркала не достучится: добавляй пакеты через `EXTRA_APT_PACKAGES` и пересобирай образ.
- Dockerfile переехал в `docker/Dockerfile`, compose остался в корне.
- Volume с домашкой контейнера назван явно: `HOME_VOLUME`, по умолчанию `opencode_opencode-home`, то есть прежнее имя. Сначала он был общим для всех репозиториев; позже визард стал выводить его на каждый репозиторий отдельно (см. запись выше). Смоуки берут свой `oc-tNN-home` и общую не трогают.
- Образ называется по compose-проекту, `opencode-server:<имя проекта>`, а не `opencode-server:local`: репозитории с разным тулчейном не подменяют друг другу образ. После обновления образ один раз пересоберётся.
- Дефолт `EXTRA_APT_PACKAGES` больше не содержит `python3-dev`.
- `make` теперь в образе всегда: в большинстве проектов задачи запускаются через Makefile, и агенту он нужен так же, как человеку.
- Если `~/.agents` нет, визард спрашивает, где лежат глобальные скиллы агента, и запоминает путь в `HOST_AGENTS_DIR`. Раньше он молча пропускал этот mount.
- Вопросы да/нет в визарде на повторном запуске по Enter оставляют сохранённый ответ: git push по ssh и питон-профиль больше не отключаются молча.
- Путь к ssh-ключу визард делает абсолютным и отвергает `"`, `\`, `$`, `:` и переводы строк. `GIT_SSH_COMMAND` пишется в `.env` только после того, как записан override с mount ключа; при отказе перезаписать override старая настройка остаётся, а в итоговом списке появляется строка об этом. В `GIT_SSH_COMMAND` добавлен `BatchMode=yes`.
- Ключ с passphrase визард больше не предлагает «всё равно взять»: он возвращает к выбору ключа, стадию можно пропустить вводом `-`.
- Проверка colima mount смотрит на `WORKSPACE/.git`, а не на произвольный файл, и честно говорит, если проверить нельзя. Путь передаётся в `colima ssh` через POSIX-кавычки.
- Контейнер запускается без capabilities (`cap_drop: ALL`), с `no-new-privileges` и лимитом процессов (`pids_limit: 1024`). `start_period` healthcheck вырос с 60 секунд до 5 минут: первая установка opencode в медленной сети больше не обрывает `up --wait`. `stop_grace_period` стал 30 секунд, больше окна остановки в entrypoint, поэтому `docker compose down` не добивает контейнер SIGKILL.
- Пустой `WORKSPACE` даёт понятную ошибку compose во всех местах подстановки, а не только в `working_dir`.

### Исправлено

- Визард больше не стирает ошибку сборки: если `docker compose up -d --build` падает или сервер не отвечает, он ждёт Enter, прежде чем очистить экран итогом, и подсказывает `docker compose --progress plain build` для полного лога сборки по шагам.
- Корпоративные `*.crt` не попадали в доверенные, если в базовом образе уже стоял `ca-certificates`: раньше их регистрировал только postinst пакета, а на таком образе он не срабатывает. Теперь `update-ca-certificates` вызывается явно. Заодно шаги `RUN` идут под `pipefail`, а проверка источников переписана с `find | grep -q` на glob, подмена корпоративных `*.sources` работает как раньше.
- `docker compose down` во время первой загрузки бинарика opencode кончался SIGKILL посреди записи: ловушка сигналов ставилась уже после загрузки. Теперь она ставится до запуска любого дочернего процесса. По TERM и INT entrypoint передаёт сигнал детям, ждёт до 10 секунд, добивает оставшихся SIGKILL и выходит с кодом 143, а не 0, так что остановку по сигналу видно.
- `OPENCODE_UPDATE_HOUR=09` ломал арифметику (восьмеричное число), а `24` и `abc` вели себя так же. Цикл обновления падал, entrypoint завершался и контейнер без внятной причины уходил в бесконечный рестарт. Теперь значение проверяется на старте: только цифры, 0-23. При ошибке скрипт один раз печатает имя переменной и допустимый диапазон и выходит с ненулевым кодом до любой загрузки.
- colima не стартовала с `overlapping mounts not supported`, если репозиторий лежит внутри `$HOME` и его передали отдельным mount. Визард теперь передаёт `--mount` для репозитория только вне `$HOME`, а `--mount $HOME:w` всегда.
- Визард на colima считал непримонтированным репозиторий, который в VM на самом деле виден, и останавливался на стадии «Репозиторий внутри движка». lima 2.x сама квотирует аргументы `colima ssh`, и путь к `.git` получал кавычки дважды. Теперь проверка уходит в shell VM через stdin.
- Апдейтер переживает моргнувшую сеть: запросы к opencode.ai идут с пятью попытками, таймаутом на соединение и только по https. Раньше один упавший запрос на первом старте валил entrypoint, и контейнер уходил в рестарт-цикл. Установщик теперь скачивается в файл целиком и выполняется только после успешной загрузки. Если установщик падает на своей загрузке бинарника, повторяется весь шаг: скачивание установщика и его запуск, с теми же пятью попытками. Версию из ответа API апдейтер сверяет с форматом `X.Y.Z`; на мусоре (HTML-заглушка прокси, сменившийся формат) пишет понятную ошибку и не отдаёт её установщику. Проверка: `tests/updater-retries.sh` (stub `curl`, без docker).
