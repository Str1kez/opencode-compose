# opencode-compose

Поднимает сервер opencode v2 в контейнере на Debian slim. С ним работаешь из браузера на хосте. Я сделал это для мака, на котором бинарник opencode запустить нельзя: MDM помечает его и убивает при старте. Docker при этом работает, так что opencode живёт в контейнере, а наружу торчит только веб-интерфейс на `127.0.0.1`.

Что внутри:

- рабочая папка (один репозиторий или папка с несколькими) монтируется на запись по тому же абсолютному пути, что и на хосте;
- `~/.config/opencode` и `~/.gitconfig` хоста монтируются только на чтение;
- сервер закрыт паролем (HTTP basic auth) и опубликован только на `127.0.0.1`;
- раз в сутки контейнер проверяет новую версию opencode, ставит её и перезапускается;
- по желанию: `git push` из контейнера отдельным deploy-ключом и питон-профиль с uv.

## Что нужно

- Docker-движок и `docker compose` v2. Подойдёт любой: colima, OrbStack, Docker Desktop. Я рекомендую colima, установка и её подвох с папками вне `$HOME` описаны в [docs/setup/engine.md](docs/setup/engine.md).
- `bash`, `make` и `git` на хосте. На маке они есть после `xcode-select --install`.
- Конфиг opencode (`~/.config/opencode`) и git-конфиг с `user.name` и `user.email` (`~/.gitconfig`). Если они лежат в другом месте, визард спросит путь.
- Для git push из контейнера: `ssh` и `ssh-keygen` на хосте и отдельный deploy-ключ без passphrase ([docs/setup/git-ssh.md](docs/setup/git-ssh.md)).
- Для `make bump-uv`: uv на хосте. Остальному харнессу он не нужен.

Питон, node и тулчейн проектов на хосте не нужны: всё, что нужно агенту, ставится в образ.

Если движка ещё нет:

```sh
brew install colima docker docker-compose
colima start
```

## Запуск

Склонируй харнесс вне папки, где лежат твои репозитории, например в `~/opencode-compose`, и запусти визард:

```sh
make
```

Почему вне: агент в контейнере пишет во всю рабочую папку, и харнесс внутри неё он переписал бы так, что следующий `make` выполнит его код на хосте. Визард такую рабочую папку не примет. Подробно в [docs/setup/workspace.md](docs/setup/workspace.md#харнесс-не-может-лежать-в-рабочей-папке).

Визард идёт по 11 шагам: проверяет Docker и конфиги, спрашивает рабочую папку (на colima проверяет, что она видна в VM), задаёт пароль сервера, порт и час обновления, базовый образ и пакеты, питон-профиль, git push по ssh, дополнительные папки и порты хоста. Потом он пишет `.env` и `docker-compose.override.yml`, собирает и поднимает контейнер, а в конце открывает браузер и кладёт пароль в буфер обмена.

Визард можно перезапускать: сохранённые значения он предлагает по Enter, включая ответы да/нет. Перезапусти его, когда в рабочей папке появился новый питон-проект или ssh-хост.

При первом старте контейнер скачивает opencode с opencode.ai, это может занять несколько минут. Готовый сервер пишет в лог (`docker compose logs -f`):

```
[opencode-update] 2026-11-10 00:17:33 installing opencode 2.2.6
[opencode-update] 2026-11-10 00:17:42 next update check in 13338s (daily at 4:00 Europe/Moscow)
server listening on http://0.0.0.0:4096
```

Открой `http://localhost:<порт>`, порт визард показывает в конце. Логин `opencode`, пароль лежит в `.env` в строке `OPENCODE_SERVER_PASSWORD`. Провайдера моделей подключи прямо в веб-интерфейсе, там же проходит OAuth.

## Прежде чем давать агенту недоверенный ввод

Контейнер не песочница. Агент пишет в `.git/` каждого репозитория рабочей папки, и хостовый git (IDE, промпт шелла) выполнит подложенную им команду. Между репозиториями внутри рабочей папки границы нет. Что именно не защищено и что проверять после сессий, описано в [docs/setup/security.md](docs/setup/security.md).
