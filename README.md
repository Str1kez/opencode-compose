# opencode-compose

Поднимает сервер opencode v2 в контейнере на Debian slim. С ним работаешь из браузера на хосте. Я сделал это для мака, на котором бинарник opencode запустить нельзя: MDM помечает его и убивает при старте. Docker при этом работает, так что opencode живёт в контейнере, а наружу торчит только веб-интерфейс на `127.0.0.1`.

Что внутри:

- рабочий репозиторий монтируется на запись по тому же абсолютному пути, что и на хосте;
- `~/.config/opencode` и `~/.gitconfig` хоста монтируются только на чтение;
- сервер слушает `0.0.0.0:4096` внутри контейнера и закрыт паролем (HTTP basic auth);
- раз в сутки контейнер проверяет новую версию opencode, ставит её и перезапускается.

## Что нужно

- Docker Desktop или OrbStack, `docker compose` v2;
- `~/.config/opencode` и `~/.gitconfig` на хосте (если их нет, compose упадёт с понятной ошибкой, а не создаст пустую папку).

## Запуск через визард (самый кайф)

```sh
make
```

Визард проверяет Docker и конфиги, спрашивает путь к репозиторию, генерирует пароль, пишет `.env` и `docker-compose.override.yml`, собирает и поднимает контейнер, а в конце открывает браузер с паролем в буфере обмена. Его можно перезапускать: уже сохранённые значения он предлагает по Enter.

## Запуск руками

```sh
cp .env.example .env
```

В `.env` заполни минимум две переменные:

```sh
WORKSPACE=/Users/me/work/my-repo
OPENCODE_SERVER_PASSWORD=<вывод openssl rand -base64 32>
```

Если Docker Hub недоступен или тормозит, укажи в `.env` Debian-образ, который уже лежит локально, например `BASE_IMAGE=debian:bookworm-slim`.

```sh
docker compose up -d --build
docker compose logs -f
```

При первом старте контейнер скачивает opencode с npm, это может занять несколько минут. Готовый сервер пишет в лог:

```
[opencode-update] 2026-11-10 00:17:33 installing opencode 2.2.6
[opencode-update] 2026-11-10 00:17:42 next update check in 13338s (daily at 4:00 Europe/Moscow)
server listening on http://0.0.0.0:4096
```

Открой `http://localhost:4096`. Браузер спросит логин и пароль: логин `opencode`, пароль из `OPENCODE_SERVER_PASSWORD`.

## Провайдеры моделей

В `opencode.jsonc` лежат настройки провайдеров: адреса, заголовки, модели. Ключи и OAuth-токены, полученные через `opencode auth login`, opencode v2 хранит в своей базе (`~/.local/share/opencode/opencode.db`), и с хоста они не подтянутся. Если ключ подключён в конфиге через `{file:...}` из папки конфига, он работает и в контейнере. Ключ через `{env:...}` заработает, только если добавить эту переменную в `environment` в `docker-compose.override.yml`: переменные хоста в контейнер сами не попадают. Иначе залогинься один раз в веб-интерфейсе или через CLI внутри контейнера:

```sh
docker compose exec opencode opencode auth login --server http://127.0.0.1:4096
```

Логин сохраняется в volume `opencode-home` и переживает перезапуски и обновления.

Любую команду opencode внутри контейнера запускай с `--server http://127.0.0.1:4096`. Без этого флага CLI поднимет второй, фоновый сервер со своими настройками.

## Тулчейн проекта

В образе есть только то, что нужно самому opencode: git, curl, ripgrep. Чтобы агент собирал проект и гонял тесты, нужен ещё тулчейн проекта. Системные пакеты перечисли в `EXTRA_APT_PACKAGES` в `.env` и пересобери образ:

```sh
EXTRA_APT_PACKAGES=build-essential python3-dev
```

Всё, что ставится в домашнюю папку (`uv`, Python через `uv python install`, `nvm`), агент может поставить сам. Домашняя папка лежит в volume `opencode-home`, поэтому установленное переживает перезапуски и обновления.

## Обновления

В 4:00 по `TZ` контейнер сверяет установленную версию с последней. Если вышла новая, он ставит её и перезапускается сам. Если версия та же, ничего не происходит. Час задаёт `OPENCODE_UPDATE_HOUR`. Перезапуск обрывает агента, если тот в этот момент работает.

Проверить и обновить руками:

```sh
docker compose exec opencode opencode-update check
docker compose restart
```

## Тонкие места

- Абсолютные симлинки в `~/.config/opencode` (например, `plugins -> ~/dotfiles/...`) в контейнере никуда не ведут. Контейнер перечисляет их при старте строками `warning: broken symlink`. Цель такой ссылки надо смонтировать по тому же пути, пример лежит в `docker-compose.override.yml.example`. Туда же можно добавить глобальные скиллы из `~/.agents`.
- `127.0.0.1` и `localhost` в конфиге opencode внутри контейнера означают сам контейнер. Если провайдер или MCP ходит в локальный прокси на хосте, впиши его порт в `HOST_LOOPBACK_PORTS` в `.env` (визард находит такие порты в конфиге сам). Контейнер пробросит `localhost:<порт>` на тот же порт хоста, и конфиг менять не придётся.
- `include` и `includeIf` в `~/.gitconfig` ссылаются на файлы, которых в контейнере нет. Если git в контейнере не знает `user.name`, смонтируй эти файлы через override.
- На Linux-хосте поставь в `.env` `OPENCODE_UID` и `OPENCODE_GID` из `id -u` и `id -g`, иначе файлы в репозитории будут принадлежать чужому пользователю. На маке это не нужно.
