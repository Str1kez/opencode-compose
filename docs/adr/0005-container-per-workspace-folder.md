# Контейнер на рабочую папку, а не на репозиторий

В ADR 0002 я держал один контейнер на репозиторий и обещал пересмотреть это, когда веб-переключалка проектов дозреет, а тулчейн у репозиториев окажется общим. Оба условия выполнились. В opencode v2.3.0 проект открывается из браузера через серверный пикер папок, base64-пути в URL больше нет, терминал стартует в директории проекта, конфиг проекта грузится по его директории. Тулчейн у моих репозиториев общий. N контейнеров на N портах неудобны, и в каждом приходится заново ставить зависимости и логиниться в провайдерах.

Я решил монтировать в контейнер рабочую папку: папку хоста, где лежат только репозитории, которым нужен opencode. Между проектами переключаюсь в веб-интерфейсе одного сервера. Один репозиторий остаётся частным случаем, когда рабочая папка совпадает с репозиторием.

## Граница доверия проходит по рабочей папке

Внутри рабочей папки изоляции между репозиториями нет. Агент, которому прилетела инъекция в репозитории A, пишет в код и в `.git` репозитория B и читает ssh-ключ. Гардрейл opencode `external_directory` этого не держит. Он проверяет пути инструментов `edit`, `write` и `read`, а в shell только cwd и аргументы `cd`, `pushd` и их родственников (`packages/core/src/shell/parse.ts`). `echo >> ../B/.git/config` или `python -c` проходят без вопроса. Гардрейл ловит промах честного агента, инъекцию он не ловит.

Поэтому визард просит самую узкую папку, где лежат только репозитории одного уровня доверия. На рабочем маке это `~/Documents`: кроме репозиториев там ничего нет. На личном это `~/Documents/developer`. Развести репозитории разного доверия можно только разными рабочими папками, то есть разными контейнерами.

## Consequences

- Образ собирает объединение тулчейнов всех репозиториев рабочей папки через `EXTRA_APT_PACKAGES`. Если двум репозиториям понадобятся несовместимые системные версии, вернусь к вопросу: mise в домашке или отдельные рабочие папки.
- Deploy-ключ один на рабочую папку и подключён в каждом GitLab-проекте. Отдельный ключ на репозиторий внутри одного контейнера ничего не защищает: агент читает все.
- Домашка своя у каждой рабочей папки (ADR 0004), volume `.venv` свой у каждого питон-репозитория (ADR 0003). Новый питон-репозиторий требует перезапуска визарда.
- opencode ищет конфиг (`.opencode`, `.claude`, `.agents`, `opencode.json`) вверх по дереву до `/`, а хостовый Claude Code так же собирает `CLAUDE.md`. Агент может положить такой файл в промежуточную папку, которая не входит ни в один репозиторий и поэтому не видна ни в одном `git diff`. Это побег на хост того же класса, что через `.git`.
- Саму рабочую папку нельзя делать git-репозиторием: сессии из подпапки уезжают в корень репозитория (opencode #51191).
- Обратной совместимости с сетапом на репозиторий нет, визард старые контейнеры и volume'ы не мигрирует.
