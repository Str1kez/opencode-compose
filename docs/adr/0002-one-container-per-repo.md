# Один контейнер на репозиторий, без мультипроекта в одном сервере

opencode v2 умеет держать много проектов в одном сервере: сессия несёт `location.directory`, есть `POST /session/{id}/move` для переноса сессии в другой проект. Напрашивается один харнесс на все репо сразу — как ведёт себя опенкод и агенты вообще.

Я решил держать один контейнер на репозиторий. Мультипроект-в-одном-сервере не делаю, хотя API это умеет.

## Почему, хотя API умеет

1. Тулчейн задаётся на образ через `EXTRA_APT_PACKAGES`. У разных репо он разный, в один образ без раздувания не склеить.
2. Веб-переключалка проектов в v2 сырая: переключение идёт через base64-путь в URL, с персистентностью сессий второго проекта есть открытые баги. API крепкий, UI поверх него — пока нет.
3. Изоляция чище: контейнер на репо даёт отдельный ssh-ключ, отдельные порты, отдельный `.venv` и свой compose-проект. Домашку это решение оставляло общей, но ADR 0004 это отменил: домашка теперь своя у каждого репозитория, общая только по явному выбору.

## Consequences

Несколько репо — это несколько контейнеров и портов, каждый поднимается отдельно. Для MVP приемлемо. Визард выводит из `WORKSPACE` имя compose-проекта (`COMPOSE_PROJECT_NAME`) и порт, так что `up` в одном репозитории не пересоздаёт контейнер другого. Без визарда проект называется `opencode`. `docker compose down -v` удаляет домашку этого репозитория (см. ADR 0004). Если у группы репо тулчейн общий и веб-переключалка в v2 дозреет, решение можно пересмотреть — тогда монтируется родительская папка, а сессии разводятся по `location.directory`.
