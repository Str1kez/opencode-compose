# Git-доступ по ssh

Чтобы агент делал `git push` из контейнера, нужен ключ без passphrase: ssh-agent в контейнере нет, ввести passphrase некому. Не бери для этого свой личный ключ. Заведи отдельный deploy-ключ:

```sh
ssh-keygen -t ed25519 -N '' -f ~/.ssh/id_deploy
```

Ключ один на всю рабочую папку: отдельный ключ на репозиторий внутри одного контейнера ничего не защищает, агент читает все. Публичную часть `~/.ssh/id_deploy.pub` добавь в GitLab в каждом проекте, куда агент должен пушить: в проекте `Settings > Repository > Deploy keys`, с галочкой `Grant write permissions`. Без неё push отвергнут.

## Что делает визард

Шаг «Git-доступ по SSH» показывает приватные ключи из `~/.ssh`. Если на выбранном стоит passphrase, визард не даёт его взять и возвращает к выбору ключа; пропустить шаг можно, введя `-`. Путь к ключу он делает абсолютным и отвергает пути с `"`, `\`, `$`, `:` и переводами строк, иначе они ломают mount. Ключ внутри рабочей папки он тоже не берёт: агент подменил бы его ссылкой на любой файл хоста.

Хосты визард берёт из remote всех репозиториев рабочей папки на любой глубине: из remote берётся `origin`, а если его нет, первый. known_hosts он собирает через `ssh-keyscan`. Хост, общий для нескольких репозиториев, подтверждается один раз. Тут нужно сверить fingerprint с тем, что публикует провайдер или говорит админ сервера: знакомство с хостом без сверки не защищает от подмены.

known_hosts лежит в `.git-ssh/` харнесса (она в `.gitignore`). Ключ и known_hosts монтируются в контейнер только на чтение, git ходит ими через `GIT_SSH_COMMAND` с `BatchMode=yes`: если ключ не подошёл, git падает сразу, а не ждёт ввода. `~/.gitconfig` хоста не мешает.

`GIT_SSH_COMMAND` визард пишет в `.env` только после того, как записал `docker-compose.override.yml` с mount ключа. Если ты отказался перезаписать override, старая настройка остаётся как была, а в итоговом списке появится строка, что ssh-изменение не применено.

Визард перечисляет ssh-remote всех репозиториев и напоминает добавить ключ в каждый GitLab-проект, но не проверяет, что он там есть. Если в рабочей папке нет ни одного репозитория с ssh-remote или ни один хост не попал в known_hosts, шаг падает.

## Проверка push

Когда сервер поднялся, визард делает из контейнера `git push --dry-run` по разу на каждый ssh-хост из known_hosts: из первого репозитория, который пушит на этот хост. Хосты, которых нет в known_hosts, он не проверяет, они уже стоят в итоговом списке недоделанного. Если проверять нечего, визард пишет почему. Ошибка push не останавливает визард, это только проверка.

## Повторный запуск

Повторный запуск не пересканирует хосты, которые уже лежат в `.git-ssh/known_hosts`, а спрашивает только про новые. Хосты, которых больше нет ни в одном remote, из файла уходят. Если ключ хоста сменился, старая запись остаётся и push падает: удали `.git-ssh/known_hosts` и перезапусти визард.

## Что не поддержано

Поддержан только push по ssh. Remote по https визард пропускает.

Remote через псевдоним из `~/.ssh/config` (`git@gl-work:group/repo.git`) тоже не поддержан: в контейнере этого конфига нет, и псевдоним там не разрешится. Визард узнаёт такой remote через `ssh -G`, печатает готовую команду `git -C <репозиторий> remote set-url ...` с настоящим хостом и пропускает этот репозиторий. Репозиторий без remote он тоже пропускает с сообщением.
