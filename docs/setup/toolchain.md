# Тулчейн проекта

В образе есть только то, что нужно самому opencode (git, curl, ripgrep, ssh-клиент), и `make`. Компилятора и языков там нет. Чтобы агент собирал проект и гонял тесты, нужен ещё тулчейн проекта.

## Питон-профиль

Питон-профиль включает визард (`INSTALL_UV=1` в `.env`): `uv` ставится прямо в образ. Его ставит pip в отдельной стадии сборки, в образ попадает только бинарь `uv`, а pip и питон этой стадии остаются за бортом. Версия и хэши колёс закреплены в `docker/uv-requirements.txt`.

Компилятор `build-essential` визард подставляет как значение `EXTRA_APT_PACKAGES` по умолчанию. Системного питона в образе нет: нужную версию приносит `uv sync`. Dev-библиотеки для нативных зависимостей допиши в `EXTRA_APT_PACKAGES`, например `build-essential libpq-dev libffi-dev`, и пересобери образ. Сам визард их не угадывает.

Если pypi.org закрыт, смотри [корпоративную сеть](corporate-network.md#pypi-индекс-для-uv).

### Обновить uv

```sh
make bump-uv UV_VERSION=0.14.0
docker compose up -d --build
```

Первая команда перезаписывает `docker/uv-requirements.txt`: новая версия и sha256 всех её файлов с PyPI. Ей нужен uv на хосте. Если версии нет на PyPI, команда падает, а прежний файл остаётся как был. Закоммить файл вместе с остальным: его читает сборка.

## Свой `.venv` у контейнера

У контейнера свой `.venv`: отдельный volume смонтирован поверх `.venv` каждого питон-проекта. Хостовый venv собран под macOS и в Linux бесполезен, поэтому контейнер его не видит и не перезаписывает, а твой `uv sync` на хосте не ломает контейнерный. Подробности в [ADR 0003](../adr/0003-container-venv-isolated-from-host.md).

Питон-проект для визарда — папка на любой глубине рабочей папки, где лежит `pyproject.toml`, а выше внутри рабочей папки другого `pyproject.toml` нет. `.git`, `.venv` и `node_modules` визард не обходит. Список питон-проектов он показывает на шаге образа и ещё раз в самом конце и каждому даёт свой volume. Volume'ы и точки монтирования он пишет в `docker-compose.override.yml`, а сборке передаёт список точек через аргумент `VENV_MOUNT_POINTS`, чтобы образ создал их с владельцем opencode.

На хосте в каждом питон-проекте остаётся пустая папка `.venv`: это точка монтирования. Визард создаёт недостающие сам.

Появился новый питон-проект (склонировал репозиторий или завёл `pyproject.toml`): перезапусти визард. Пока этого не сделано, у нового проекта нет своего `.venv`-volume, и контейнерный `uv sync` пишет в хостовый `.venv`.

Если на повторном запуске питон-проекты пропадают из override, визард перечисляет их до вопроса о перезаписи. Если ты их не убирал, ищи `pyproject.toml` над ними, например в корне рабочей папки: он делает все проекты под собой вложенными.

Без визарда `.venv` контейнера настраивается руками, смотри [запуск без визарда](manual-setup.md#питон-проекты).

## Другие стеки

Для остальных стеков перечисли системные пакеты в `EXTRA_APT_PACKAGES` в `.env` и пересобери образ:

```sh
EXTRA_APT_PACKAGES=build-essential libpq-dev
```

В домашнюю папку агент может ставить что угодно (`nvm`, Python через `uv python install`, свои бинарники). Она лежит в volume `HOME_VOLUME` этой рабочей папки, поэтому установленное переживает перезапуски и обновления. У другой рабочей папки свой volume и своя установка.
