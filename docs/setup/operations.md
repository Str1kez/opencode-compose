# Работа с сервером

## Провайдеры моделей

В `opencode.jsonc` лежат настройки провайдеров: адреса, заголовки, модели. Ключи и OAuth-токены провайдеров opencode v2 хранит в своей базе (`~/.local/share/opencode/opencode.db`), и с хоста они не подтянутся. Если ключ подключён в конфиге через `{file:...}` из папки конфига, он работает и в контейнере. Ключ через `{env:...}` заработает, только если добавить эту переменную в `environment` в `docker-compose.override.yml`: переменные хоста в контейнер сами не попадают. Иначе подключи провайдера один раз прямо в веб-интерфейсе, там же проходит и OAuth. Команда в контейнере для этого не нужна.

Логин сохраняется в домашнем volume рабочей папки (`HOME_VOLUME`) и переживает перезапуски и обновления. В другой рабочей папке логиниться придётся заново, подробности в разделе [про домашнюю папку](workspace.md#домашняя-папка-контейнера).

## Команды opencode внутри контейнера

Любую команду opencode внутри контейнера запускай с `--server http://127.0.0.1:4096`. Без этого флага CLI поднимет второй, фоновый сервер со своими настройками. По той же причине не запускай в контейнере `opencode service restart`: он поднимает второй сервер на той же базе. Перезапуск сервера — `docker compose restart`.

## Обновления

В 4:00 по `TZ` контейнер сверяет установленную версию с последней. Если вышла новая, он ставит её и перезапускается сам. Если версия та же, ничего не происходит. Час задаёт `OPENCODE_UPDATE_HOUR`. Перезапуск обрывает агента, если тот в этот момент работает.

Проверить и обновить руками:

```sh
docker compose exec opencode opencode-update check
docker compose restart
```

Лог: `docker compose logs -f`. Остановить: `docker compose down`.

## Тонкие места

- Абсолютные симлинки в `~/.config/opencode` (например, `plugins -> ~/dotfiles/...`) в контейнере никуда не ведут, если их цель не смонтирована по тому же пути. Визард находит такие симлинки в конфиге и в `~/.agents` и монтирует их цели сам. Если цель появилась позже, перезапусти визард. Контейнер перечисляет оставшиеся при старте строками `warning: broken symlink`.
- Глобальные скиллы из `~/.agents` и глобальный gitignore из `~/.config/git` визард подключает по твоему подтверждению. Если скиллы лежат в другой папке, он спросит путь.
- `127.0.0.1` и `localhost` в конфиге opencode внутри контейнера означают сам контейнер. Если провайдер или MCP ходит в локальный прокси на хосте, впиши его порт в `HOST_LOOPBACK_PORTS` в `.env` (визард находит такие порты в конфиге сам). Контейнер пробросит `localhost:<порт>` на тот же порт хоста, и конфиг менять не придётся.
- `include` и `includeIf` в `~/.gitconfig` ссылаются на файлы, которых в контейнере нет. Если git в контейнере не знает `user.name`, смонтируй эти файлы через override.
- На Linux-хосте контейнер должен работать под твоим UID и GID, иначе файлы в рабочей папке будут принадлежать чужому пользователю. Визард пишет `OPENCODE_UID` и `OPENCODE_GID` в `.env` сам, без визарда поставь их из `id -u` и `id -g`. На маке это не нужно.
