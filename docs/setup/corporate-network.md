# Корпоративная сеть

## apt-зеркало

Если `deb.debian.org` закрыт и пакеты идут через внутреннее зеркало, укажи визарду папку с apt-настройками зеркала, он скопирует их в `docker/apt/`. Туда же их можно положить руками. Файлы `*.sources` и `*.list` заменяют стандартные источники Debian, `*.conf` ложатся в `apt.conf.d` (прокси, логин, `CAInfo`), `*.crt` становятся доверенными сертификатами в образе. Формат и пример лежат в [docker/apt/README.md](../../docker/apt/README.md). Всё, кроме README, в `.gitignore`, так что адреса зеркала в репозиторий не попадут.

`*.conf` действуют только во время сборки и в образ не попадают, так что логин и прокси зеркала не оседают в его слоях. Поэтому логин клади в `*.conf`, а не в адрес внутри `*.sources`: источники и сертификаты в образе остаются. Обратная сторона: `apt-get install` руками внутри запущенного контейнера в корпоративной сети до зеркала не достучится. Нужные пакеты добавляй через `EXTRA_APT_PACKAGES` в `.env` и пересобирай образ.

## Базовый образ

Базовый образ берётся из `BASE_IMAGE`, по умолчанию `debian:trixie-slim`. Если Docker Hub закрыт или тормозит, укажи в `.env` образ из внутреннего registry или Debian, который уже лежит локально (`docker images debian`). Визард сам предлагает локальный Debian, если `debian:trixie-slim` ещё не скачан. Подойдёт любой образ на Debian: сборке нужен apt.

## PyPI-индекс для uv

uv в питон-профиле pip берёт из PyPI-индекса `UV_PIP_INDEX_URL`, по умолчанию `https://pypi.org/simple`. Если pypi.org закрыт, укажи визарду адрес корпоративного индекса, например `https://nexus.example.corp/repository/pypi/simple`. Нужен только https-адрес без логина: http pip не примет, а логин и пароль в адресе визард отклонит.

Хэши в `docker/uv-requirements.txt` закрепляют ровно те файлы uv, что опубликованы на PyPI под этой версией, так что индекс с подменённым uv сборку уронит. pip доверяет корпоративным `*.crt` из `docker/apt`, а `python3-pip` для стадии идёт через то же apt-зеркало. Прокси из apt-шных `*.conf` pip не видит: если индекс доступен только через прокси, задай его для сборок в `~/.docker/config.json`, как описано ниже. Адрес индекса виден только стадии с pip, в истории готового образа его нет.

Без питон-профиля (`INSTALL_UV=0`) стадия с pip не собирается вовсе, и индекс сборке не нужен.

## Прокси для контейнера

Без прокси контейнер не скачает opencode с opencode.ai и не достучится до провайдеров: compose не передаёт `HTTPS_PROXY`. Править compose не нужно. Docker сам подставляет прокси в контейнеры и сборки из клиентского конфига `~/.docker/config.json`:

```json
{
  "proxies": {
    "default": {
      "httpProxy": "http://proxy.example.com:3128",
      "httpsProxy": "http://proxy.example.com:3128",
      "noProxy": "localhost,127.0.0.0/8,.example.org"
    }
  }
}
```

Конфиг подхватывается без перезапуска Docker, но только для новых контейнеров и сборок. После правки пересобери образ и пересоздай контейнер: `docker compose up -d --build`. Логин и пароль в адресе прокси попадут в переменные окружения контейнера открытым текстом, их видно через `docker inspect`. Эти настройки работают только внутри контейнеров: для самого демона Docker (скачивание образов) прокси задаётся отдельно. Описание: https://docs.docker.com/engine/cli/proxy/.
