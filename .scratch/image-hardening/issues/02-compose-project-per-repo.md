# 02: Несколько репозиториев одновременно

**What to build:** Харнесс можно поднять в двух репозиториях сразу, и они не мешают друг другу. Сейчас имя compose-проекта зашито как `opencode`, поэтому `up` во втором репозитории пересоздаёт контейнер первого. Это прямо противоречит ADR 0002. У каждого репозитория свой compose-проект: визард выводит его имя из WORKSPACE так же, как уже выводит имя volume с `.venv`, и пишет в `.env`. Порт сервера визард тоже разводит по репозиториям.

Home-volume остаётся общим и получает явное имя. Дефолт имени равен текущему `opencode_opencode-home`, поэтому логин opencode, история и скачанный бинарь переживают переход без миграции. Per-repo home отвергнут: повторный логин и повторная закачка бинаря в каждом репозитории. Ограничение «на нескольких живых контейнерах история сессий общая» уходит в README. Пункт 3 ADR 0002 («отдельная домашка») правится под это решение.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**Модель реализации:** opus, high — новый контракт между визардом и compose, том с данными пользователя, откатить трудно

- [ ] имя compose-проекта задаётся из `.env`, визард выводит его из WORKSPACE, дефолт без визарда остаётся `opencode`
- [ ] home-volume назван явно, дефолт совпадает с существующим `opencode_opencode-home`, данные в нём не теряются
- [ ] два репозитория поднимаются одновременно на разных портах, `up` в одном не трогает контейнер другого
- [ ] повторный запуск визарда в уже настроенном репозитории сохраняет его имя проекта
- [ ] ADR 0002 и README обновлены: общий home, ограничение по истории сессий
- [ ] оба смоука зелёные; смоуки по-прежнему не трогают проект `opencode` и его volume
