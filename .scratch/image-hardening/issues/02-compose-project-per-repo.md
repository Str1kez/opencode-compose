# 02: Несколько репозиториев одновременно

**What to build:** Харнесс можно поднять в двух репозиториях сразу, и они не мешают друг другу. Сейчас имя compose-проекта зашито как `opencode`, поэтому `up` во втором репозитории пересоздаёт контейнер первого. Это прямо противоречит ADR 0002. У каждого репозитория свой compose-проект: визард выводит его имя из WORKSPACE так же, как уже выводит имя volume с `.venv`, и пишет в `.env`. Порт сервера визард тоже разводит по репозиториям.

Home-volume остаётся общим и получает явное имя. Дефолт имени равен текущему `opencode_opencode-home`, поэтому логин opencode, история и скачанный бинарь переживают переход без миграции. Per-repo home отвергнут: повторный логин и повторная закачка бинаря в каждом репозитории. Ограничение «на нескольких живых контейнерах история сессий общая» уходит в README. Пункт 3 ADR 0002 («отдельная домашка») правится под это решение.

**Blocked by:** None (can start immediately).

**Status:** resolved

**Модель реализации:** opus, high — новый контракт между визардом и compose, том с данными пользователя, откатить трудно

## Comments

- home-volume: имя и дефолт `opencode_opencode-home` проверены через `docker compose config`; живой `up` поверх существующего volume не гонялся, демона нет.
- два репозитория одновременно: через `docker compose config` проверено, что у двух `.env` разные проект, порт, сеть, образ и venv-volume при общем home; живой `up` двух контейнеров не гонялся, демона нет.
- смоуки не запускались, демона нет. В оба добавлен свой `HOME_VOLUME=oc-tNN-home`, иначе их `down -v` удалил бы общий home; через `docker compose config -p oc-t04` видно, что home у смоука свой.
- 2026-11-15, OrbStack 29.8.2, ветка `task-image-hardening` после мёрджа всех тикетов: `tests/smoke-git-push.sh` и `tests/smoke-python-venv.sh` зелёные.
- Смоуки взяли свои `oc-tNN-home`, после прогона томов `oc-t*` не осталось. Два живых репозитория одновременно не поднимались.
- Решение сверх тикета: образ тегируется по проекту, `opencode-server:${COMPOSE_PROJECT_NAME}` вместо `opencode-server:local`. С общим тегом пересборка во втором репозитории перетегировала бы образ, и следующий `up -d` в первом пересоздал бы его контейнер с чужим тулчейном. Цена: после обновления образ один раз пересобирается.
- Живая проверка на OrbStack после фиксов ревью (проекты `oc-t09`, `oc-t10`, общий `HOME_VOLUME`): оба контейнера healthy на 4109 и 4110, `up` второго не пересоздал первый (тот же container id), compose предупреждает про volume другого проекта, как описано в README.
