# 01: Апдейтер переживает моргнувшую сеть

**What to build:** Контейнер на первом старте не уходит в рестарт-цикл, если сеть до opencode.ai моргнула. Сейчас один упавший запрос в установке бинаря валит entrypoint, compose перезапускает контейнер, и всё повторяется без внятной причины. Запросы апдейтера получают ретраи, таймаут на соединение и только https. Установщик скачивается целиком и только потом выполняется: обрыв на середине больше не запускает половину скрипта. Версию из ответа API апдейтер проверяет по формату и на мусоре (HTML-заглушка прокси, сменившийся формат) пишет понятную ошибку, а не передаёт его установщику.

`OPENCODE_SHA256` из аудита не делаем: хеш бинаря меняется с каждой версией, а апдейтер ставит новую ежедневно.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**Модель реализации:** sonnet, medium — правка одного скрипта, но меняется старт контейнера

- [ ] запросы апдейтера идут с ретраями, таймаутом на соединение и запретом не-https
- [ ] установщик скачивается в файл и выполняется только после успешной загрузки
- [ ] версия не по формату `X.Y.Z` даёт понятную ошибку и не уходит в установщик
- [ ] проверено на заглушке `curl`, которая падает дважды и отвечает с третьего раза: установка проходит
