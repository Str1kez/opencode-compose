# 05: Живая проверка рабочей папки на рабочем маке

**What to build:** Подтверждение вживую того, что я не смог проверить по коду opencode. Визард прогоняется на реальной рабочей папке с несколькими репозиториями (минимум два питон-репозитория и один без питона). Проверяется в браузере, что проект переключается, терминал открывается в папке выбранного проекта, проект, добавленный из браузера, переживает `docker compose restart`, а контейнерный `uv sync` не меняет хостовый `.venv` ни одного репозитория. Результат пишется в комментарий тикета.

## Comments

2026-11-18. Рабочая папка на colima с 10 питон-проектами, у каждого свой `.venv`-volume. Визард, установка и переход между репозиториями в браузере работают. Сессии и проекты пережили два `docker compose down` + `up -d`: в базе их нет только до 23:43, когда визард создал новый home-volume рабочей папки. В контейнере нельзя запускать `opencode service restart`: он поднимает второй сервер на той же базе, и opencode вставляет в сессию ложное сообщение о рестарте. Провайдер подключается прямо в веб-интерфейсе, команда в контейнере не нужна, README и финальный экран визарда поправлены.

Git-доступ по SSH в этом сетапе не включён: push делается с хоста, ключ агенту не нужен. Логику стадии покрывают `tests/wizard-functions.sh` и `tests/smoke-git-push.sh`.

Не проверено: терминал в папке проекта, `uv sync` против хостового `.venv`.
