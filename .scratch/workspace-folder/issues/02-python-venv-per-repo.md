# 02: Свой `.venv` на каждый питон-репозиторий

**What to build:** В рабочей папке с несколькими питон-репозиториями контейнерный `uv sync` не затирает хостовые macOS-`.venv`. Визард обходит рабочую папку без лимита глубины, пропуская `.git`, `.venv` и `node_modules`, и берёт самые верхние `pyproject.toml`: те, у которых нет предка с `pyproject.toml` внутри рабочей папки. Подпроект под чужим `pyproject.toml` оверлея не получает, об этом визард молчит. Если рабочая папка сама питон-репозиторий, volume встаёт на `WORKSPACE/.venv`, как сейчас.

На каждый найденный проект визард заводит named volume поверх его `.venv`. Имя выводится из рабочей папки и относительного пути с контрольной суммой, по принципу нынешнего `VENV_VOLUME`. Список mount'ов и volume'ов пишется в `docker-compose.override.yml`, единственный `workspace-venv` из `docker-compose.yml` уходит. Каталог `.venv` на хосте визард создаёт, если его нет: это точка монтирования. В конце стадии визард печатает список найденных питон-репозиториев и предупреждение: новый питон-репозиторий требует перезапуска визарда, иначе контейнерный `uv sync` перезапишет его хостовый `.venv`. Повторный запуск обновляет override и сохраняет остальные настройки.

Решения: [ADR 0003](../../../docs/adr/0003-container-venv-isolated-from-host.md) (раздел «После ADR 0005»), [ADR 0005](../../../docs/adr/0005-container-per-workspace-folder.md).
