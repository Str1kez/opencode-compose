# 04: Питон-тулчейн и разводка .venv

**What to build:** Питон-проект собирается и гоняет тесты в контейнере, не конфликтуя с хостовым `.venv`. Отдельный volume поверх `WORKSPACE/.venv` разводит хостовый и контейнерный venv, так что `uv sync` внутри создаёт рабочий Linux-venv, а хостовый macOS-venv остаётся нетронутым. Визард отдельным шагом предлагает питоновский профиль поставки: `build-essential` (gcc для сборки колёс) и uv прямо в образ, без системного питона и `python3-dev`, плюс поле, куда вписать native dev-библиотеки проекта. Решение зафиксировано в ADR 0003.

**Blocked by:** None (can start immediately, параллельно 01 и 02).

**Status:** resolved

**Модель реализации:** sonnet, medium — volume поверх `.venv` и шаг визарда по готовым швам (решение в ADR 0003)

- [x] отдельный volume примонтирован поверх `WORKSPACE/.venv`; хостовый `.venv` в контейнере не виден
- [x] `uv sync` внутри контейнера создаёт рабочий Linux-`.venv`, не затрагивая хостовый
- [x] `.venv` лежит на стандартном пути; `.venv/bin/python` в контейнере запускается
- [x] визард отдельным шагом предлагает питон-профиль: `build-essential` и uv в образ
- [x] системный питон и `python3-dev` в образ не ставятся
- [x] uv ставится в образ, а не оставлен агенту в `~/.local`
- [x] визард даёт дописать dev-библиотеки проекта поверх профиля (libpq-dev, libffi-dev и подобные)
- [x] дефолт `EXTRA_APT_PACKAGES` больше не содержит `python3-dev`
- [x] смоук: на тестовом питон-проекте в контейнере `uv sync` проходит и `.venv/bin/python -c` отрабатывает
- [x] `shellcheck` на `scripts/setup.sh` чист
