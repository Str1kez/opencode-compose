# 01: uv в образ через pip из заданного индекса

**What to build:** В корпоративной сети нет ни ghcr.io, ни registry с образом uv, поэтому питон-профиль там не собирается. Вариант через образ `astral-sh/uv` уходит совсем. Остаются два варианта: питон-профиль выключен, тогда uv не ставится, или включён, тогда uv ставится через pip в отдельной стадии сборки из PyPI-индекса, адрес которого спрашивает визард. По умолчанию индекс `https://pypi.org/simple`, логин индексу не нужен, передаётся только URL.

Стадия с pip одноразовая: в финальный образ копируется только бинарь `uv`, системного питона там по-прежнему нет (ADR 0003). Стадия строится на `BASE_IMAGE` и берёт `python3-pip` через то же корпоративное apt-зеркало и с теми же сертификатами из `docker/apt`, что и финальная, поэтому apt-сетап надо сделать применимым в любой стадии. `*.conf` при этом в слои не попадают.

При `INSTALL_UV=0` стадия с pip вообще не строится и сборка никуда за uv не ходит. Это закрывает известное ограничение: сейчас стадия uv резолвится всегда и в закрытой сети роняет сборку не-питон проекта.

Версия uv остаётся прежней (0.13.8). Закрепление переезжает с digest образа на хэши wheel'ов: `--require-hashes` с хэшами для linux amd64 и arm64 (colima на Apple silicon собирает arm64). Нужен `--only-binary :all:`, потому что sdist uv собирается через Rust. Подводный камень: pip на Debian trixie по PEP 668 отказывается ставить пакеты в системный питон, способ установки в стадии должен это обходить, а не ломать.
