# 01: Агент выполняет команды на хосте через `.git`

**What to build:** Решение по границе между контейнером и хостовым git. Находка (Medium): `docker-compose.yml` монтирует на запись весь `WORKSPACE`, включая `.git/`. Скомпрометированный агент пишет `core.fsmonitor`, `core.hooksPath` или `.git/hooks/*`, и хостовый git (IDE, промпт шелла) выполняет эти команды при любом `git status`. То же работает для вложенного репозитория, который агент создаёт в подпапке.

Предложенное исправление «вложенные read-only bind-mount на `.git/config` и `.git/hooks`» **отвергнуто после проверки**:

- (a) в контейнере с такими RO-монтированиями `git remote add o2 /x` падает с `fatal: could not set 'remote.o2.url' to '/x'`. Запись конфига ломается, значит, ломаются `push -u` и настройка tracking.
- (b) `.git/commondir` остаётся писабельным. На хостовом git 2.55.0 репозиторий, у которого `.git/commondir` указывает на каталог с `config` с `core.fsmonitor`, выполнил эту команду на `git status`. Обход не трогает `.git/config`.
- (c) `mv .git .git-old` в контейнере проходит, несмотря на вложенные монтирования, так что агент кладёт рядом свежий `.git`.
- (d) вложенные репозитории в подпапках не покрыты вообще.

Единственное настоящее исправление: агент работает в отдельном клоне, изменения доходят до хоста через push/fetch. Цена: пропадает один и тот же абсолютный путь и живое редактирование из IDE. Решение за пользователем.

**Blocked by:** None (can start immediately).

**Status:** ready-for-human

**Исполнение:** человек — выбор между отдельным клоном и принятым риском
